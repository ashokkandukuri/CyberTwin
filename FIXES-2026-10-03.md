# CyberTwin — Final Incident Correlation Fix

## Fix applied
Standalone `RISK_CHANGED`, `IMPACT_CHANGED`, mitigation, and recovery events no longer create a new security incident when there is no existing incident to correlate them with.

A new incident may now be opened only by security-originating events:
- `ATTACK_STARTED`
- `ATTACK_DETECTED`
- `ANOMALY_DETECTED`
- `DEVICE_DEGRADED`
- `DEVICE_COMPROMISED`

This prevents benign target-criticality risk updates from creating noisy standalone incidents after a previous incident has recovered.

## Preserved behavior
The tested DoS lifecycle remains unchanged:

`ATTACK → RISK → IMPACT → MITIGATION RECOMMENDED → MITIGATION APPLIED → IMPACT LOW → RECOVERY`

The existing incident continues to collect risk, impact, mitigation, and recovery evidence.
